## 2. 规则更新流程

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                          规则更新流程 (秒级更新)                               │
└─────────────────────────────────────────────────────────────────────────────┘

步骤 1: 管理员更新规则
┌──────────────────┐
│  RuleManagerCLI  │
│  (规则管理工具)   │
└────────┬─────────┘
         │
         │ UPDATE quality_rules SET ...
         ▼
┌──────────────────┐
│      MySQL       │
│  (规则持久化)     │
└────────┬─────────┘
         │
         │ 规则更新成功
         ▼

步骤 2: 发布 Redis 通知
┌──────────────────┐
│ RedisRulePublisher│
│  (发布器)         │
└────────┬─────────┘
         │
         │ PUBLISH rule_changes "RULE_UPDATED:123"
         ▼
┌──────────────────┐
│      Redis       │
│  (Pub/Sub 频道)  │
└────────┬─────────┘
         │
         │ 推送通知到所有订阅者
         ▼

步骤 3: Flink 接收通知 (< 5 秒)
┌─────────────────────────────────────────────────────────────┐
│  Flink TaskManager (并行度 = 4)                              │
│                                                             │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐     │
│  │  Subtask 1   │  │  Subtask 2   │  │  Subtask 3   │ ... │
│  │              │  │              │  │              │     │
│  │  Redis 订阅   │  │  Redis 订阅   │  │  Redis 订阅   │     │
│  │  线程        │  │  线程        │  │  线程        │     │
│  │              │  │              │  │              │     │
│  │  onMessage() │  │  onMessage() │  │  onMessage() │     │
│  │      ↓       │  │      ↓       │  │      ↓       │     │
│  │ refreshRules │  │ refreshRules │  │ refreshRules │     │
│  └──────────────┘  └──────────────┘  └──────────────┘     │
└─────────────────────────────────────────────────────────────┘

步骤 4: 刷新规则
┌──────────────────┐
│ RuleCacheManager │
│  (缓存管理器)     │
└────────┬─────────┘
         │
         │ getAllRules()
         │ Caffeine → Redis → MySQL
         ▼
┌──────────────────┐
│   RuleEngine     │
│  (规则引擎)       │
└────────┬─────────┘
         │
         │ updateRules(newRules)
         │ 更新内存中的规则
         ▼
┌──────────────────┐
│  规则更新完成     │
│  开始使用新规则   │
└──────────────────┘
```

## 3. 双重刷新机制

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                          双重刷新机制 (主要 + 兜底)                            │
└─────────────────────────────────────────────────────────────────────────────┘

机制 1: Redis Pub/Sub (主要机制)
┌──────────────────────────────────────────────────────────────┐
│  触发方式: 规则变更时主动推送                                  │
│  延迟: < 5 秒                                                │
│  可靠性: 99% (可能因网络问题丢失消息)                          │
│  作用: 实时更新，提供最佳用户体验                              │
└──────────────────────────────────────────────────────────────┘
         │
         │ 规则变更通知
         ▼
┌──────────────────┐
│  Redis 订阅线程   │
│  (后台线程)       │
└────────┬─────────┘
         │
         │ onMessage()
         ▼
┌──────────────────┐
│  refreshRules()  │
│  (synchronized)  │
└──────────────────┘


机制 2: Flink Timer (兜底机制)
┌──────────────────────────────────────────────────────────────┐
│  触发方式: 定时触发 (1 分钟)                                   │
│  延迟: 最多 60 秒                                             │
│  可靠性: 100% (Flink 保证)                                    │
│  作用: 兜底机制，防止消息丢失，确保最终一致性                   │
└──────────────────────────────────────────────────────────────┘
         │
         │ 每 1 分钟触发
         ▼
┌──────────────────┐
│   Flink Timer    │
│  (定时器)         │
└────────┬─────────┘
         │
         │ onTimer()
         ▼
┌──────────────────┐
│  refreshRules()  │
│  (synchronized)  │
└──────────────────┘


线程安全保障:
┌──────────────────────────────────────────────────────────────┐
│  synchronized (refreshLock) {                                │
│      // 同一时刻只有一个线程在刷新                             │
│      List<QualityRule> newRules = cacheManager.getAllRules();│
│      ruleEngine.updateRules(newRules);                       │
│  }                                                           │
└──────────────────────────────────────────────────────────────┘
```

## 4. 线程模型

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    Flink TaskManager 线程模型                                 │
└─────────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────────┐
│  Flink TaskManager JVM 进程                                                  │
│                                                                             │
│  ┌───────────────────────────────────────────────────────────────────────┐ │
│  │  Flink 主线程 (数据处理)                                               │ │
│  │                                                                       │ │
│  │  processElement(order) {                                             │ │
│  │      // 1. 注册 Timer (首次)                                          │ │
│  │      if (nextRefreshTime == null) {                                  │ │
│  │          ctx.timerService().registerProcessingTimeTimer(...);        │ │
│  │      }                                                               │ │
│  │                                                                       │ │
│  │      // 2. 校验数据                                                   │ │
│  │      ValidationResult result = ruleEngine.execute(order);            │ │
│  │                                                                       │ │
│  │      // 3. 输出结果                                                   │ │
│  │      out.collect(order);                                             │ │
│  │  }                                                                   │ │
│  │                                                                       │ │
│  │  onTimer(timestamp) {                                                │ │
│  │      refreshRules();  // 定时刷新                                     │ │
│  │      ctx.timerService().registerProcessingTimeTimer(...);  // 注册下次 │ │
│  │  }                                                                   │ │
│  └───────────────────────────────────────────────────────────────────────┘ │
│                                                                             │
│  ┌───────────────────────────────────────────────────────────────────────┐ │
│  │  Redis 订阅线程 (后台线程, daemon)                                     │ │
│  │                                                                       │ │
│  │  while (subscriberRunning) {                                         │ │
│  │      jedis.subscribe(new JedisPubSub() {                             │ │
│  │          @Override                                                   │ │
│  │          public void onMessage(String channel, String message) {     │ │
│  │              refreshRules();  // 接收通知，立即刷新                    │ │
│  │          }                                                           │ │
│  │      }, REDIS_CHANNEL);                                              │ │
│  │  }                                                                   │ │
│  └───────────────────────────────────────────────────────────────────────┘ │
│                                                                             │
│  ┌───────────────────────────────────────────────────────────────────────┐ │
│  │  RuleCacheManager 后台线程 (30 秒刷新缓存)                             │ │
│  │                                                                       │ │
│  │  scheduler.scheduleAtFixedRate(() -> {                               │ │
│  │      refresh();  // 刷新三层缓存 (MySQL → Redis → Caffeine)           │ │
│  │  }, 30, 30, TimeUnit.SECONDS);                                       │ │
│  └───────────────────────────────────────────────────────────────────────┘ │
│                                                                             │
│  ┌───────────────────────────────────────────────────────────────────────┐ │
│  │  共享资源 (线程安全)                                                   │ │
│  │                                                                       │ │
│  │  - RuleEngine (规则引擎)                                              │ │
│  │  - RuleCacheManager (缓存管理器)                                      │ │
│  │  - refreshLock (刷新锁)                                               │ │
│  └───────────────────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────────────────────┘
```

## 6. 故障恢复流程

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                          故障恢复流程                                         │
└─────────────────────────────────────────────────────────────────────────────┘

场景 1: Redis 连接失败
┌──────────────────┐
│  Redis 订阅线程   │
└────────┬─────────┘
         │
         │ jedis.subscribe() 失败
         ▼
┌──────────────────┐
│  捕获异常         │
│  LOG.error()     │
└────────┬─────────┘
         │
         │ 等待 5 秒
         ▼
┌──────────────────┐
│  自动重连         │
│  while (running) │
└────────┬─────────┘
         │
         │ 重试成功
         ▼
┌──────────────────┐
│  恢复订阅         │
│  继续接收通知     │
└──────────────────┘

兜底机制:
┌──────────────────┐
│  Flink Timer     │
│  (1 分钟刷新)     │
└────────┬─────────┘
         │
         │ 即使 Redis 失败
         │ Timer 仍然工作
         ▼
┌──────────────────┐
│  refreshRules()  │
│  最终一致性保证   │
└──────────────────┘


场景 2: 消息丢失
┌──────────────────┐
│  Redis 消息丢失   │
│  (网络问题)       │
└────────┬─────────┘
         │
         │ Flink 未收到通知
         ▼
┌──────────────────┐
│  等待最多 60 秒   │
└────────┬─────────┘
         │
         │ Timer 触发
         ▼
┌──────────────────┐
│  refreshRules()  │
│  规则最终更新     │
└──────────────────┘


场景 3: 并发刷新冲突
┌──────────────────┐         ┌──────────────────┐
│  Redis 订阅线程   │         │  Flink Timer     │
└────────┬─────────┘         └────────┬─────────┘
         │                            │
         │ refreshRules()             │ refreshRules()
         │ (同时触发)                  │ (同时触发)
         ▼                            ▼
┌─────────────────────────────────────────────────┐
│  synchronized (refreshLock) {                   │
│      // 第一个线程获得锁，执行刷新                │
│      // 第二个线程等待                           │
│  }                                              │
└─────────────────────────────────────────────────┘
         │                            │
         │ 刷新完成                    │ 等待锁
         ▼                            ▼
┌──────────────────┐         ┌──────────────────┐
│  释放锁           │         │  获得锁           │
└──────────────────┘         └────────┬─────────┘
                                      │
                                      │ 发现规则已是最新
                                      │ 跳过刷新
                                      ▼
                             ┌──────────────────┐
                             │  释放锁           │
                             └──────────────────┘
```

## 7. 监控指标

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                          监控指标                                             │
└─────────────────────────────────────────────────────────────────────────────┘

指标 1: Redis 订阅者数量
┌──────────────────────────────────────────────────────────────┐
│  命令: redis-cli PUBSUB NUMSUB rule_changes                  │
│  预期值: = Flink 并行度 (例如: 4)                             │
│  异常: < 并行度 (说明部分 Subtask 订阅失败)                    │
└──────────────────────────────────────────────────────────────┘

指标 2: 规则刷新延迟
┌──────────────────────────────────────────────────────────────┐
│  测量: 规则更新时间 - Flink 日志时间                          │
│  预期值: < 5 秒 (Redis Pub/Sub)                              │
│  兜底值: < 60 秒 (Flink Timer)                               │
│  异常: > 60 秒 (说明两种机制都失败)                           │
└──────────────────────────────────────────────────────────────┘

指标 3: 规则刷新成功率
┌──────────────────────────────────────────────────────────────┐
│  测量: 成功刷新次数 / 总刷新次数                              │
│  预期值: > 99%                                               │
│  异常: < 95% (说明缓存或数据库有问题)                         │
└──────────────────────────────────────────────────────────────┘

指标 4: 规则数量
┌──────────────────────────────────────────────────────────────┐
│  测量: ruleEngine.getRuleCount()                             │
│  预期值: > 0                                                 │
│  异常: = 0 (说明规则加载失败)                                 │
└──────────────────────────────────────────────────────────────┘

Flink Metrics:
┌──────────────────────────────────────────────────────────────┐
│  - totalRecords: 总处理记录数                                 │
│  - validRecords: 校验通过记录数                               │
│  - invalidRecords: 校验失败记录数                             │
│  - recordsPerSecond: 吞吐量 (条/秒)                           │
│  - maxLatencyMs: 最大处理延迟 (毫秒)                          │
│  - minLatencyMs: 最小处理延迟 (毫秒)                          │
│  - avgLatencyMs: 平均处理延迟 (毫秒)                          │
└──────────────────────────────────────────────────────────────┘
```

## 总结

✅ **双重保障**: Redis Pub/Sub (< 5s) + Flink Timer (< 60s)  
✅ **线程安全**: synchronized 锁防止并发刷新  
✅ **自动重连**: 订阅失败自动重试  
✅ **性能优化**: 后台线程，不阻塞主流程  
✅ **可观测性**: 完善的日志和监控  
✅ **故障恢复**: 自动重连 + 兜底机制
